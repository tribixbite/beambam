# beambam.boo

Landing + docs site for the [beambam](https://pypi.org/project/beambam/)
Python package — a signed-MQTT bridge + daemon stack for Bambu Lab 3D
printers (X1, P1, A1, H2, X2D, P2S, X1E). LAN-first, no cloud account
required.

## Design Context

### Users
3D-printing hobbyists and makers who own Bambu Lab printers, technical
enough to type `pip install` and SSH into their own homelab. Heavy
overlap with the sysadmin / Home Assistant / Termux-on-Android
audience. Many arrive frustrated: the official Bambu Studio + Network
Plugin doesn't run on their machine (aarch64 Linux, no plugin),
or they refuse to log into a cloud account just to print over their
LAN. They want a tool that respects their intelligence and gives them
real control.

Common journeys:
- Search "bambu lab without cloud" / "x2d termux" / "p1s home assistant"
- Linked from r/3Dprinting, Hacker News, the bambulab GitHub issue tracker
- Trying to set up Home Assistant integration when ha-bambulab won't connect to signed-MQTT firmware
- Looking for the print-plan analyzer after seeing the eevee 3-color flush-storm post

### Brand personality
**Opinionated. Mechanical. Terse.**

Like a workshop tool catalog or a 1970s machine-shop manual — not a
2025 startup landing page. The author is a hacker who built this for
themselves and shared it; the site should sound like that, not like
marketing-copy generated by a content team.

- "Pure-Python signed-MQTT bridge" beats "AI-powered 3D printing
  automation platform"
- Numbers (28 commands, 300 tests, 12 printer models) carry the
  weight that adjectives ("comprehensive", "powerful", "elegant")
  would in a worse design
- Footnotes and asterisks are fine; this is a technical document
- The voice is closer to a build journal than a brochure

### Aesthetic direction
**Machine-shop blueprint, not SaaS landing page.**

Warm filament-amber on cool steel-graphite. Generous negative space.
Monospace for technical content (commands, code, identifiers, tables).
Sharp grid alignment — not asymmetric chaos, but precise like
engineering drawings. Diagrams over icons.

Theme: **dark by default** — the audience is overwhelmingly homelab /
night-printing / SSH terminal users. Light mode optional but secondary.

**References to mine**:
- Klim Type Foundry (klim.co.nz) — generous spacing, almost-zero color, type does the work
- Tinybird docs — dense technical content in clear grids
- Cabin journal (cabinjournal.com) — editorial seriousness
- Bambu Studio CLI man pages (if they existed)
- Eurorack synthesizer manuals (long-form technical, diagram-heavy, surprisingly beautiful)

**Anti-references** (the current site falls into these traps):
- Every Vercel / Linear / Resend landing page from 2023+
- Tailwind template "Build something amazing" hero
- 6-card feature grid with rounded-icon-above-heading pattern
- Gradient blobs in the background
- "AI-generated tech startup" aesthetic — neon cyan on dark, purple-blue gradients, glassmorphism cards

### Design principles

1. **Numbers > adjectives.** "28 commands, 12 printer models, 300 tests"
   teaches the reader more than "powerful comprehensive bridge."
2. **Show the tool.** Real CLI output, real code snippets, real
   diagrams — not stock-photo screenshots of "happy users."
3. **Grid like a blueprint.** Aligned, measured, captioned. Asymmetry
   only when it serves the page (e.g. one bold header offset
   left-aligned with running body text below — but always intentional).
4. **One distinctive display face + a refined mono.** No third font.
   The display carries the brand, the mono carries the work.
5. **Color is rare.** Amber accent on ≤10% of the page. The rest is
   graphite + paper. Color earns its appearance.
6. **Footnotes are honest.** If a feature has a caveat (compatibility,
   firmware version, region), say so inline in a footnote. The audience
   wants accuracy more than confidence.
